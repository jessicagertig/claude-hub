# Plato AI — DB slice (migrations + data migrations + schema)

Scope: schema/data-migration surface only. All tables are AI-feature-owned except the JOBS table columns and Organization.settings, which are SHARED surfaces.

## New tables (all AI-owned)

- **ai_job_application_summaries** — one row per generated candidate summary. Cols: `job_application_id` (FK, not null), `textract_result_id` (FK, nullable), `structured_data` (jsonb), `headline`, `summary_text`, `status` (int enum, default 0), `error_message`, `stale` (bool default false), `requested_by_organization_user_id` (bigint, no FK), `score_percentage` (decimal), `criteria_results` (jsonb), `integrated_role_analysis` (text). Holds both the summary text AND the scoring output (score/criteria/analysis). Indexed on (job_application_id, created_at) and status.
- **ai_api_requests** — audit log of every provider LLM call. Polymorphic `requestable_type`/`requestable_id` (not null), `call_type`, `provider`, `model`, `input_tokens`/`output_tokens` (default 0), `cost` (decimal 10,6 default 0), `prompt_text`, `response_body`. Belongs to organization. This is the raw record of pipeline calls (provider/model/prompt/response per step) — relevant to the scoring manifest as ground truth of what actually ran.
- **organization_ai_credit_balances** — one-to-one with organization (unique index). Buckets: `daily_credits_remaining`, `monthly_credits_remaining`, `addon_subscription_credits_remaining`, `addon_credits_remaining` (all not null default 0, each with a `>= 0` CHECK constraint), plus `monthly_ai_credits_override`, `last_reset_at`, low/zero notification timestamps + `sent_low/zero_notification_since_increase` flags. The CHECK constraints mean any code path that would drive a bucket negative raises at the DB — user-visible as a failed action rather than a silent over-spend.
- **ai_credit_balance_transactions** — ledger. `organization_ai_credit_balance_id` (FK), `organization_ai_credit_purchase_id` (nullable FK, added in 040501), `entry_type` (int enum), `bucket` (int enum), `amount` (int), `description`, `metadata` (jsonb). Every credit grant/consume/refund writes a row.
- **organization_ai_credit_purchases** — subscription + one-off purchase records. `kind` (int enum), Stripe ids (`stripe_subscription_id`, `stripe_checkout_session_id`, `stripe_invoice_id`, `stripe_price_lookup_key` not null), `amount_cents_paid` (later RENAMED → `stripe_amount`), `currency` (default usd), subscription period/credits/status/cancel fields, `refunded_at`. Partial-unique indexes on stripe_subscription_id and stripe_checkout_session_id (where not null). Later migrations add `stripe_invoice_paid` (bool default false), `stripe_invoice_item_id`, and `last_updated_by_organization_user_id` (FK → organization_users).
- **bulk_ai_summary_job_applications** — tracks bulk-generate batches. `bulk_job_id` (uuid), `job_application_id`, `status` (int enum default 0). Partial-unique index on job_application_id WHERE status = 0 (processing) — enforces one in-flight bulk summary request per application; a second bulk enqueue for the same application while one is processing hits the constraint.
- **ai_job_criteria** — one row per job's extracted scoring criteria. `job_id` (FK), `status` (int enum), `criteria` (jsonb), `metadata` (jsonb), `error_message`. Index on job_id was created UNIQUE (120000) then CHANGED to non-unique (204646) — so a job can now have multiple criteria-generation rows (history), not just one.
- **ai_job_application_summary_statuses** — companion status record, one-to-one with job_application (unique index). `ai_job_application_summary_id` (nullable FK), `status` (int enum default 0), plus DENORMALIZED `score_percentage`, `headline`, `integrated_role_analysis` copied from the summary. This is the record the candidate-list/table UI reads to show per-applicant AI state and score without loading the full summary.

## SHARED surfaces touched (regression risk)

- **jobs table** (SHARED — core model). Added: `auto_generate_ai_summaries` (int default 0, 040701), `ai_job_application_summaries_count` (int not null default 0) and `ai_job_criteria_generations_count` (int not null default 0) — both counter_culture counter caches — and `internal_job_criteria` (text, 182504). Risk: the two counter-cache columns must stay in sync with child-row create/destroy; the data migration 182505 (`AiJobApplicationSummaryStatus.counter_culture_fix_counts`) backfills them. Any job serializer/index that now returns these columns could shift job payloads. The counter caches increment/decrement on every AI summary/criteria row lifecycle event on an otherwise non-AI model.
- **Organization.settings** (SHARED jsonb settings hash). Data migration 040802 writes 5 new AI keys to EVERY existing org's settings via `update_settings`: `auto_generate_ai_summaries_enabled: false`, `hiring_team_ai_credits_control_enabled: true`, `low_ai_credit_notifications_enabled: false`, `low_ai_credit_notification_threshold: 0`, `zero_ai_credit_notifications_enabled: true`. Risk: mutating the shared settings hash for all orgs — verify no non-AI setting was clobbered and defaults are the intended out-of-box AI state.

## Data migrations (backfill — states/edge cases)

- **040801** creates one OrganizationAiCreditBalance per existing org (idempotent: `next if exists?`), seeding `monthly_credits_remaining` from `PlanFeatureGate.new(org).monthly_ai_credit_allocation`, addon = 0. Uses `.create` (not `create!`) and logs failures without aborting — a failed org silently has no balance row. down = `delete_all`.
- **040802** backfills the 5 org AI settings (above). Per-org rescue/log, does not abort. down only runs in development.
- **182505** runs `counter_culture_fix_counts` to backfill the new jobs counter-cache columns. Irreversible.

## QA-relevant gating conditions
- Fresh orgs get a balance + settings via app callbacks; the 2 backfill migrations only matter for pre-existing orgs. Per hub failure-pattern #17/#19: these data migrations show "up" even if a schema rollback wiped their data.
- ai_job_criteria job_id index went unique→non-unique: don't assume one criteria row per job in UI.
- bulk partial-unique index blocks a duplicate in-flight bulk summary for the same application (status=0).
- Balance bucket CHECK constraints (>= 0) turn an over-consume into a hard error, not a negative balance.
