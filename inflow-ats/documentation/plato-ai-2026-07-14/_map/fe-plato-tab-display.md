## PlatoTab.tsx — core behavior (the thing to QA)

Data sources: `jobApplication.aiJobApplicationSummaryStatus` (status row: `status`, `aiJobApplicationSummaryId`, `headline`, `scorePercentage`, `updatedAt`), the `useAiJobApplicationSummary` hook (full summary incl. `status`, `structuredData`, `integratedRoleAnalysis`, `criteriaResults`, `stale`), and `useOrganizationAiCreditBalance` (`totalCreditsRemaining`).

Status-row `statusValue` gates the top-level render:
- `current` or `regenerating` + `fullSummary` present → **renders the full review** (`renderSucceeded` → `PlatoSummary`). `hasContent` true → header gets a bottom border.
- `regenerating` → header-right shows a spinning sparkle chip + "Regenerating"; content still shows the prior review underneath.
- In-flight full-summary statuses (`pending`, `textract_processing`, `extracting`, `summarizing`, `awaiting_job_criteria`, `scoring`, `integrating`, `retrying`, or `succeeded` without structuredData) OR local `showPlatoLoading` → **PlatoLoadingState** (4-step progress animation).
- `fullSummaryStatus === "failed"` → **PlatoTabEmptyState status="failed"** ("Plato couldn't analyze… No credit was used. Try again").
- No status / `none` + `!hasResume` → empty state `noResume` (button routes to the resume tab via `history.push` replacing last URL segment with `/resume`).
- Otherwise → empty state from `deriveEmptyStatus()`: `noCredits` (credits ≤ 0), `bulkQueued` (`jobApplication.bulkAiSummaryProcessing`), else `ready`.

USER ACTIONS enabled:
- **Generate review** (empty states `ready`/`bulkQueued`/`failed`) → `handleGenerate` calls `useGenerateAiSummary`; on success sets local `showPlatoLoading=true` (optimistic switch to loading UI); on error shows a warning toast (10s) using `error.data.errors.general[0]` or "Failed to queue summary".
- **Regenerate** (only when `statusValue==="current"` AND `fullSummary.stale` AND credits>0 or still loading) → `handleClickRegenerate` opens a `ConfirmationModal` ("Uses 1 credit of N remaining"), confirm → `handleGenerate`. Regenerate button passes `loading`/`disabled` = `buttonLoading` (isLoadingCredits || isGenerating) — double-click guarded.
- **Buy credits** when stale + out of credits: admins get an internalLink to `/hire/settings/plato-ai/billing`; non-admins get a "Buy credits" button opening an "Admin access required" CenterModal.

Edge cases / gates:
- `showPlatoLoading` is force-cleared when `regenerationSettled` (statusValue==="regenerating" OR fullSummaryStatus==="failed") — done inline in render (`if (showPlatoLoading && regenerationSettled) setShowPlatoLoading(false)`), a setState-during-render pattern; watch for double-render / flicker on transition into regenerating or failure.
- `creditError` → treated as 0 remaining (blocks generation via noCredits path).
- Out-of-credits empty state: admin gets a working "Buy credits" link to `/hire/settings/plato-ai/billing`; non-admin gets a DISABLED button (`buttonDisabled`) and the member message. NOTE the two billing URLs differ: AiSummaryState (orphaned) uses `/hire/settings/ai-billing`; live PlatoTab & PlatoTabEmptyState use `/hire/settings/plato-ai/billing`. Verify the live route resolves.

## PlatoSummary.tsx — review layout

Renders: meta line ("Generated by Plato · <ago>"), optional stale banner, fit score tag + FitStars, headline, primary/secondary domains, "Fit for this role" prose block (`roleFit` = `integratedRoleAnalysis || structuredData.roleAnalysis || summaryText`), ScoringDetail accordion, notable achievements (`assessment.standoutAccomplishments`), relevant experience, open questions (`gaps`), skills chips (key skills sorted first + styled via separate KeySkillChip vs SkillChip — matches the "separate styled variants" rule), and a disclaimer footer. All sections conditionally render only when their data is present — empty arrays/strings hide the block. `scorePct` (from `summaryStatus.scorePercentage`) drives `fitBand`.

## FitIndicator.tsx — score→band mapping (relevant to scoring QA)

`fitBand(pct)` thresholds: ≥90 excellent(5★) / ≥60 good(4★) / ≥35 mixed(3★) / ≥15 weak(2★) / else poor(1★). `fitTagVariant`: excellent+good → gradient "linear" tag, others → "light". FitStars renders 0–5 gradient-filled sparkles. These bands are the user-facing interpretation of the numeric `scorePercentage` — verify a candidate's percentage lands in the expected band/label.

## ScoringDetail.tsx — criteria breakdown

Groups `criteriaResults` into tier_1 "Core criteria" / tier_2 "Preferred criteria" / tier_3 "Bonus criteria"; within a tier sorts by score rank full_match→partial_match→not_found. Header tally shows counts of met/partial/missing. `not_found` rows rendered greyed. Empty tiers are dropped. Consumes `CriterionResult { tier, score, criterionText, reasoning }` — confirm serializer field names match.

## PlatoLoadingState.tsx — progress animation

4 fixed steps (Processing resume / Analyzing candidate / Scoring against role / Finalizing). `STATUS_TO_STEP` maps backend status→step index: textract_processing→0, extracting/summarizing→1, awaiting_job_criteria/scoring→2, integrating→3. Active step index only ever moves forward (`Math.max(prev, target)`). After 10s shows "You can keep working — Plato will finish in the background." Reduced-motion disables the spinner.

## SHARED / non-AI surfaces that could regress

- **JobApplicationActivity.tsx** (activity feed): new `platoReview` feed-item type renders **PlatoGeneratedReviewCallout** with `headline/roleFit/scorePct/updatedAt`; "See full review" pushes to the `/ai` tab. A malformed/missing `platoReview` feed item, or a change to how other feed item types render, could regress the candidate activity timeline for ALL candidates (not just AI ones). Verify non-AI activity items (comment/review/etc.) still render.
- **JobStagesContainer.tsx** via **RunPlatoCtaCardV1** (uses PlatoSparkleIcon): a CTA card on the stages/pipeline view — outside this slice's tab but shares PlatoSparkleIcon. Not deeply traced here.
- URL routing: both generate-empty-state and the activity callout do `match.url.replace(/\/[^/]+$/, "")` + append `/resume` or `/ai`. If the candidate drawer route shape changes, these pushes could land on the wrong tab.

No pipeline/model/provider code in this slice (pure FE display).
