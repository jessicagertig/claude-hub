# Finding: issue1-autogen-no-summary

## TRACER FINDING

### issue
No AiJobApplicationSummary is created on any auto-generate entry before Textract resolves. Jessica believes auto-gen ON should create an AiJobApplicationSummary immediately on the auto-gen submission (status textract_processing if Textract is not ready yet), for every auto-gen submission. The observed incident (failed TextractResult, no AiJobApplicationSummary, AiJobApplicationSummaryStatus row present) is exactly what the current code produces.

### title
Auto-generate never pre-creates a textract_processing AiJobApplicationSummary; the summary-creating path is only reached after Textract succeeds AND a summary already exists

### is_real_gap
True

### gap_confidence
proven

### current
On every auto-gen entry, NO AiJobApplicationSummary is created before (or at) submission. (1) enqueue_new_job_application (job_application.rb:164-171) enqueues NewJobApplicationJob, DocxToPdfJob, the Flipper-gated SubmitResumeToTextractJob, and find_or_create_ai_job_application_summary_status (the STATUS row only, :170) — it never calls CreateAiSummaryGeneration and never builds an AiJobApplicationSummary, and never reads should_auto_generate_ai_summaries?. (2) The auto-gen decision lives ONLY in the bridge TextractResult#queue_ai_summary_job else branch (textract_result.rb:137-143), which reads should_auto_generate_ai_summaries? at :138 — confirmed sole caller (grep: only textract_result.rb:138). (3) The bridge fires only via after_commit on textract_job_result_text being present and changed (textract_result.rb:115-116); it is only set on Textract SUCCESS (get_resume_text_from_textract.rb:24-31 .update). A FAILED Textract writes update_columns(textract_job_status: 'failed') (get_resume_text_from_textract.rb:40) which neither touches textract_job_result_text nor fires callbacks, so the bridge never runs for a failed/never-ready Textract — the auto path never executes at all. (4) Even on Textract SUCCESS with auto-gen ON and no pre-existing summary, the else branch enqueues GenerateAiJobApplicationSummaryJob (textract_result.rb:142), whose pipeline returns early without creating a summary: Orchestrate#call returns at orchestrate.rb:16 (@ai_job_application_summary nil) BEFORE run_summary→Summary::Generate (generate.rb:35-39, the sole first-summary creator) is reached, then generate_ai_summary_with_credit_flow returns at textract_result.rb:82 (self.ai_job_application_summaries empty on the new result). So no summary, no credit, no broadcast. This holds for all auto-gen entries traced: T1 (job_application.rb:164-171), T3 clone (map 193: case 1 outcome), T4 apply (map 217: case 1), T5 import (map 230: case 1), T8 backfill (enqueues SubmitResumeToTextractJob only, queue_bulk_ai_summary_jobs.rb:28-30), T2 resume-replacement (map 174: stale-succeeded → case 3, no new summary). The only AiJobApplicationSummary status:textract_processing CREATION site in the whole app is the manual single-send analog create_ai_summary_generation.rb:47-53 (grep confirmed; submit_resume_to_textract.rb:18/25 and orchestrate/generate only query or reuse existing rows).

### intended
On every auto-gen submission (auto-gen ON for the job, gates pass), an AiJobApplicationSummary should be created IMMEDIATELY at the entry, before Textract resolves. If Textract is not yet ready, that summary should be status: textract_processing so it is visible and is the record the bridge later advances (the if/handoff branch). This mirrors the manual single-send analog (CreateAiSummaryGeneration), which builds a textract_processing summary at create_ai_summary_generation.rb:47-53 when validation_result.textract_pending is true.

### delta
The auto-gen flow has NO equivalent of CreateAiSummaryGeneration's pre-create step. The auto-gen decision is made only at the bridge (post-Textract-success), and the bridge's else branch creates no summary when none pre-exists. Therefore for any auto-gen application whose Textract fails or is never ready, zero AiJobApplicationSummary records ever exist — exactly the incident. The fix is to pre-create a textract_processing AiJobApplicationSummary on the auto-gen entry, gated like the bridge (should_auto_generate_ai_summaries? + ValidateAiSummaryGeneration), mirroring the analog.

### later_resolved_check
Checked all later actors. (a) The bridge (textract_result.rb:114-144) only fires on Textract success and, with no pre-existing summary, takes case 1 (creates nothing). (b) Summary::Generate create path (generate.rb:35-39) is unreachable without a pre-existing summary because Orchestrate returns at orchestrate.rb:16 first — confirmed by the intended-behavior spec orchestrate_spec.rb:40-46 ('when no summary exists → returns silently', Summary::Generate not instantiated). (c) GetResumeTextFromTextractJob retry-exhaustion cleanup_orphaned_summary (get_resume_text_from_textract_job.rb:10-23) only DESTROYS a textract_processing summary; it never creates one and returns at :16 when none exists. (d) ExtractJobCriteria / X3 resume_waiting_summaries (ai_job_criteria.rb) advance EXISTING waiting summaries, never create the first one. (e) No backfill/replay creates a summary on failed-textract auto-gen. Conclusion: no later actor resolves the missing-summary state for an auto-gen entry; it is a true gap, not a resting state.

### solution_critique
Approach 1 (mirror the analog: pre-create a textract_processing summary at the auto-gen entry, gated by should_auto_generate_ai_summaries? + ValidateAiSummaryGeneration) is sound and the analog is a genuine match: CreateAiSummaryGeneration.build at create_ai_summary_generation.rb:47-53 builds exactly status:textract_processing with requested_by_organization_user_id (nullable -- schema.rb:157 confirms nil allowed). This is an OPEN DECISION for Jessica, correctly flagged. (4) cleanup_orphaned_summary now DESTROYS the auto-created textract_processing summary on terminal Textract failure (get_resume_text_from_textract_job.rb:19) and broadcasts to OrganizationUser.find_by(id: nil) -> nil -> broadcast_ai_summary_failed returns at :147 (no toast). Jessica's stated expectation ('that summary should be textract_processing so it is visible') implies she may want it to PERSIST as failed, contradicting destroy-on-exhaustion. This is the single most important open decision and the audit correctly surfaces it.
