## Rules Added to ~/claude-hub/inflow-ats/CLAUDE.md

- **Rule 27 — Conventions review must be scoped one reviewer per rules file, not one broad "compliance" angle.** Motivated by Phase 6.5: impl rounds 1-3 each ran a broad cursor-rules-compliance angle across ~30 rules files and produced 0 MED conventions findings; the per-rules-file fan-out (25 reviewers) found 10 MED + ~20 LOW on the same diff, including a functional gap (missing query error state) and the backend/_base.md §8 `reload` violation.
- **Rule 28 — Spec display-state enumerations must include query lifecycle states (fetch error), not only payload-driven states.** Motivated by conventions-pass component-architecture.md F1 (MED): SPEC §8.2's table ("single source of truth: the fetched payload", rows 0-5) had no fetch-error row; `JobCriteriaSection.tsx` destructured only `data`/`isLoading`/`isFetching`, so a failed GET rendered the never-extracted empty state with a Generate criteria button. Survived 5 spec rounds, 2 plan passes, and 3 impl rounds (frontend-display-states angle ran every round).
- **Rule 29 — rspec is not in the pre-commit gate; contract-tightening changes must update and run every affected spec file, and never assume base is green.** Verified: `package.json` `"pre-commit": "bash bin/run-cypress-precommit && lint-staged"` — no rspec. Motivated by two develop-side breakages surfaced this run: PR #3054 made `rescore_requested` required without updating 4+ existing request examples (red on develop, impl-round-2 verdict + round-3 operational-concerns), and 9 pre-existing `on_complete` failures in `bulk_generate_ai_summaries_job_spec.rb` at the branch base (impl-round-1 operational-concerns).
- **Rule 30 — Specs asserting on associations read during creation callbacks must reload before driving the code under test.** Motivated by the develop-merge reconciliation (impl-round-2 test-coverage.md item 3): `textract_result_ai_trigger_spec.rb` needed `job_application.reload` because `JobApplication` creation callbacks read `latest_ai_job_application_summary` (find_or_create_ai_job_application_summary_status.rb:62), caching the has_one as nil before the spec created `waiting_summary`; without the reload, the manual-waiting branch of textract_result.rb:126 would never have been exercised — silent ghost coverage.
