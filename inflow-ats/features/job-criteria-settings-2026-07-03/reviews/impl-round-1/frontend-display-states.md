## Findings

- F1 [HIGH] app/javascript/ats/src/views/jobApplications/jobSetup/components/JobCriteriaSection.tsx:148-157 (Button at :151 `loading={isInFlight}`) / The Generate/Regenerate section button passes `loading={isInFlight}` but NOT `disabled={isInFlight}`, so it stays clickable while an extraction is in flight / SPEC §4.1 states the mitigation for the missing pending guard verbatim: "The frontend disables the button once the payload shows an in-flight status; residual double-enqueue is wasteful but harmless." The shared Button component does NOT block clicks on `loading` — only `disabled` prevents `onClick` (`components/shared/Button/index.js:33-37`). Consequence: while the latest row is `pending` (the one in-flight status `extract_job_criteria_immediately` deliberately does NOT guard), a user can click the loading button, get the confirm modal, confirm, and create a second pending row + a second paid extraction job. This is also the exact recurrence of pipeline rule 11's motivating failure — the closest generate-button analog passes BOTH props (`PlatoTab.tsx:239`: `loading={buttonLoading} disabled={buttonLoading}`). Note for the record: SPEC §8.3 lists only `loading={isInFlight}` for this button (internal spec tension with §4.1); adding `disabled={isInFlight}` satisfies both clauses simultaneously / Fix: add `disabled={isInFlight}` to the Generate/Regenerate `Button` in `Styled.ActionRow`. Minimum change; do not touch the View button or the modal's buttons (already correct).
