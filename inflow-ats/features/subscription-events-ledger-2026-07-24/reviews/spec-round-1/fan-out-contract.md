## Findings

- F1 [MED] SPEC §7 (canceled_subscription row) + §11.4 / nil `subscription_canceled_at` fabricates a 1970 timestamp or kills the notification / `Discord::NotifySubscriptionDeletedJob#perform(organization_id, ended_at)` — `ended_at` is a REQUIRED positional with no default, and the job runs `Time.at(ended_at)` (notify_subscription_deleted_job.rb:7,14). The fan-out passes `organization.subscription_canceled_at.to_i`: for a console/backfill-created row (§11.3) the column can be nil — `nil.to_i` → 0 → `Time.at(0)` = Jan 1 1970 in the Discord message, a fabricated value (rule 10/13); passing raw nil instead would raise TypeError inside the job (swallowed by its rescue → notification silently lost + error logged). §7 currently punts ("SPEC-PROPOSED, verify the job's argument handling at plan time") — the behavior is verifiable NOW and the spec must define it. / Fix (amendment): §7 table cell and §11.4 amended — enqueue `Discord::NotifySubscriptionDeletedJob` only when `organization.subscription_canceled_at` is present; when absent, SKIP the Discord enqueue (PostHog still fires) — never fabricate a timestamp. §9.3 gains the matching test requirement.

- F2 [MED] SPEC §2/§1.5 / removal shape in `Notification::PaidSubscriptionDeletedJob` underspecified / The spec says "remove the line-22 Discord enqueue," but line 22 is the body of the private `discord(organization_id, ended_at)` method, invoked from `perform` at line 13. A literal line-22 removal leaves a called, empty method; an over-eager removal could take the `ended_at` param with it — but `ended_at` is still consumed by the Slack path (`blocks` line 34: `@ended_at || Time.now.to_i`). Rule (hub): direct the removal shape so a fix agent doesn't guess. / Fix (amendment): §2 amended — remove the `discord(organization_id, ended_at)` call at line 13 AND the private `discord` method (lines 21–23); the `ended_at` param, `@ended_at` assignment, `slack`, and everything else stay byte-identical.

- F3 [LOW] SPEC §5.1 / second-trial edge preserved, note-only / A canceled-never-paid customer who re-checkouts can trial again (status `'canceled' → 'trialing'`), which does NOT match the exact `nil → 'trialing'` gate — no `trial_started` row, no Discord ping. This mirrors today's behavior exactly (the current Discord enqueue sits inside the same gate) and D6 pins the placement; recorded for completeness only. No amendment.

- F4 [LOW] SPEC §7 / Discord-after-ledger coupling, note-only / Once moved, a failed `CreateSubscriptionEvent` (e.g., 5-minute dedupe) means no Discord ping where today the callback always enqueues. §5.1 already acknowledges the dedupe as a deliberate guard on this writer; this is the pattern working as designed (D1). No amendment.
