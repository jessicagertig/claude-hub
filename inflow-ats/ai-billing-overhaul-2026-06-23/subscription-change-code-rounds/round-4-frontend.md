## D1 — Change-button visual style (`buttonType`) is derived from a never-populated `isMostPopular` field instead of from the button text; the analog derives it from the button text via `getPlanButtonType`

- **ANALOG (trace items 15/16):** the per-plan `buttonType` is `getPlanButtonType(buttonText)` (`AccountBillingPlans.tsx:186`; def `planLookups.js:578-584`). `getPlanButtonType` maps the BUTTON TEXT to the visual style: `"Upgrade"`/`"Start plan"`/`"Start free trial"` → `"primary"`, everything else → `"secondary"`. It is spread onto each plan (`AccountBillingPlans.tsx:188-191`) and reaches the SCREEN as `styleType={plan.buttonType || "secondary"}` on the change `Styled.Button` (`PlanCard.tsx:211`). So in the analog the structure is: **button text drives button style**, and an Upgrade action renders a primary button.
- **OURS:** `buttonType: !isSubscribed && (tier as any).isMostPopular ? "primary" : "secondary"` (`AiCreditSubscription.tsx:294`). The style is NOT derived from the button text produced by `deriveTierButtonText` (`aiSubscriptionHelpers.ts:30-39`, which returns `"Subscribe"`/`"Upgrade"`/`"Downgrade"`/`"Change plan"`); it is derived from `tier.isMostPopular`. `isMostPopular` is declared on the `AiCreditTier` interface (`AiSubscriptionTierCard.tsx:15`) and read at `AiCreditSubscription.tsx:294` and `AiSubscriptionTierCard.tsx:41`, but it is **never produced** — `aiCreditPrices` (`planHelpers.ts:104-124`) does not set it, and grep confirms zero producers in `planHelpers.ts`/`aiSubscriptionHelpers.ts`. It is therefore always `undefined`, so `buttonType` is **always `"secondary"`** and the `"primary"` branch is dead. The SCREEN terminal `styleType={tier.buttonType || "secondary"}` (`AiSubscriptionTierCard.tsx:67`) consequently NEVER renders a primary button — an "Upgrade" tier card gets a secondary button, whereas the analog's `getPlanButtonType("Upgrade")` would render it primary.
- **Structural mismatch:** the analog's button-style structure is *style ← function of button text* (`getPlanButtonType(buttonText)`); ours is *style ← function of a non-existent `isMostPopular` field*, with the button text (the analog's sole input) ignored. This diverges from the analog at a SCREEN terminal (the change button's visual variant). Not covered by SANCTIONED #1-5 or W1-W5 (none mention `buttonType`, `isMostPopular`, or `getPlanButtonType`).
- **file:line:** `AiCreditSubscription.tsx:294` (buttonType derivation), `AiSubscriptionTierCard.tsx:15`/`:41`/`:67` (dead `isMostPopular` read + `styleType` SCREEN terminal); analog `AccountBillingPlans.tsx:186`/`:188-191`, `planLookups.js:578-584`, `PlanCard.tsx:211`.
