## D1 — Subscribed-but-unmatched-plan case emits the UNSUBSCRIBED button label `"Subscribe"`; the analog emits the SUBSCRIBED fallback `"Change plan"`

- **ANALOG (trace item 15; `planLookups.js:594-619`):** the button label has two cleanly separated regimes. The UNSUBSCRIBED labels (`"Start plan"` / `"Start free trial"`) come ONLY from `getUnsubscribedPlanButtonText(hasNeverSubscribed)` (`:586-592`), reached only on the not-`hasActiveSubscription` branch (`PlanCard.tsx:103` create-new fork). For a SUBSCRIBED org, the label comes from `getPlanButtonText(currentPlanLookupKey, …)` (`:594`), whose FIRST guard is `if (!currentPlan || !targetPlan) { return "Change plan"; }` (`:607-609`). So when the org IS subscribed but its live `currentPlanLookupKey` matches no entry in `allOrganizationPlanOptions` (the lookup miss), the analog returns the SUBSCRIBED fallback **`"Change plan"`**, NOT the unsubscribed label. The unsubscribed label is gated strictly on subscription STATE, never on a plan-data lookup miss.
- **OURS (`aiSubscriptionHelpers.ts:30-37`):** `deriveTierButtonText(isSubscribed, currentCredits, tierCredits)` has `if (!isSubscribed || currentCredits == null) return "Subscribe";` (`:35`). The `|| currentCredits == null` clause routes a SUBSCRIBED org (`isSubscribed === true`) to the UNSUBSCRIBED label `"Subscribe"` whenever `currentCredits` is null. `currentCredits` is null precisely on the lookup miss: `currentSubscriptionTier = subscriptionTiers.find((tier) => tier.lookupKey === currentPlanLookupKey)` (`AiCreditSubscription.tsx:66-69`) is `undefined` when the live `currentPlanLookupKey` is absent from `AI_CREDIT_PACK_CREDITS_BY_LOOKUP_KEY` (`planHelpers.ts:74-87`, the source of each tier's `credits`), so `currentCredits = currentSubscriptionTier ? currentSubscriptionTier.credits : null` (`:70`) is null. This collapses the analog's two distinct regimes (subscription-STATE gate → unsubscribed label; plan-data lookup-miss → subscribed `"Change plan"` fallback) into one: a subscribed org with an unmatched live plan shows `"Subscribe"` buttons. It also makes the SCREEN self-inconsistent — `AiSubscriptionStatus` simultaneously renders `isSubscribed`-true `"Active subscription"` with a blank `{currentCredits?.toLocaleString()}` headline (`AiSubscriptionStatus.tsx:34-35`) while the tier buttons read `"Subscribe"`. This `"Subscribe"` text reaches the SCREEN at `{tier.buttonText}` (`AiSubscriptionTierCard.tsx:79`) and, via `deriveTierButtonType("Subscribe") === "primary"` (`aiSubscriptionHelpers.ts:45`), the `styleType` at `AiSubscriptionTierCard.tsx:77`.
- **Structural mismatch:** analog — unsubscribed label gated ONLY on `!hasActiveSubscription`; subscribed lookup-miss → `"Change plan"`. OURS — unsubscribed label `"Subscribe"` fires on `!isSubscribed` OR on a subscribed lookup miss (`currentCredits == null`). The `currentCredits == null` disjunct is the EXTRA gate the analog does not have on its unsubscribed label; the analog handles the same lookup-miss case with the subscribed `"Change plan"` fallback. To match: the unsubscribed `"Subscribe"` label must be gated on `!isSubscribed` ALONE, and the subscribed-with-null-credits case must fall through to `"Change plan"` (the analog's `!currentPlan` fallback), e.g. `if (!isSubscribed) return "Subscribe"; return (currentCredits != null && tierCredits > currentCredits) ? "Upgrade" : "Change plan";`.
- **Not covered by SANCTIONED/WHITELIST:** SANCTIONED #3 sanctions removing the job-limit GATE; #5 the `ai_credit_*` naming; W4 sanctions the local `lookupKey→credits` TABLE's existence as the rank source. None sanction routing a SUBSCRIBED org's button to the UNSUBSCRIBED label on a lookup miss. W4 explicitly states "round-2 D1/D3 (nullable `?? null` local lookup driving credits + button text) is RESOLVED" — but `currentCredits == null` STILL drives the button text here (the `|| currentCredits == null → "Subscribe"` clause), so this instance is NOT resolved and contradicts that note. The fix is in OUR code and breaks no correct behavior (the analog's own subscribed fallback is `"Change plan"`), so it is not a forced deviation.
