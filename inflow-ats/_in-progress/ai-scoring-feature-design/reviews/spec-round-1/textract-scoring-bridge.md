# textract-scoring-bridge — Round 1

## Findings

- F1 [HIGH] `BulkGenerateAiSummariesJob` does NOT call `GenerateAiJobApplicationSummaryJob` -- it calls `result.textract_result.generate_ai_summary_with_credit_flow` directly (bulk_generate_ai_summaries_job.rb line 62). The spec's Section 5 says the bulk trigger goes "BulkGenerateAiSummariesJob -> Orchestrate (per iteration)." The spec needs to clarify HOW the bulk path reaches the orchestrator. Currently, the bulk job calls `ValidateAiSummaryGeneration.call` (line 59), then `result.textract_result.generate_ai_summary_with_credit_flow` (line 62). The orchestrator replacement happens inside `generate_ai_summary` (called by `generate_ai_summary_with_credit_flow`), so the bulk path would reach the orchestrator through that chain. The spec should explicitly state this chain for the bulk path rather than implying it goes directly to Orchestrate. **Fix:** Clarify in Section 5 that the bulk path reaches the orchestrator through `TextractResult#generate_ai_summary_with_credit_flow` -> (the method that currently calls `generate_ai_summary`, which will be replaced by orchestrator call).

- F2 [MED] Spec Section 6 says "Replace the single `generate_ai_summary` method call inside `TextractResult#generate_ai_summary_with_credit_flow` with a call to `AiJobApplicationAction::Orchestrate`." This is precise and matches the code (textract_result.rb line 71). However, `generate_ai_summary` is also a standalone public method (line 52-54). The spec doesn't say whether the standalone `generate_ai_summary` method should be removed, renamed, or kept alongside the orchestrator. If kept, it becomes a way to bypass the orchestrator and run only the summary pipeline. **Fix:** State whether `TextractResult#generate_ai_summary` should be removed, deprecated, or intentionally kept as a summary-only path.

- F3 [LOW] The spec says `AiJobCriteria` `after_commit` callback enqueues `GenerateAiJobApplicationSummaryJob.perform_later(textract_result_id: summary.textract_result_id)` for each waiting summary. This re-enters the full `generate_ai_summary_with_credit_flow` path, which includes `ValidateAiSummaryGeneration` via the existing textract callback chain. Wait -- no, the job calls `textract_result.generate_ai_summary_with_credit_flow` directly (line 23), which does NOT re-validate. This is correct behavior for a resume. But the spec should note that re-entry through `GenerateAiJobApplicationSummaryJob` does NOT re-validate credits or Flipper gates -- the credit check already passed on initial entry.
