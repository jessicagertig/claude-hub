## MED-1 — Candidate list renders no fit chip when the current review's score is 0.0
The candidate-list row omits the fit chip when `AiJobApplicationSummaryStatus.score_percentage` is `0.0` ("Poor fit"), while the Overview tab, Plato tab, and the `role_fit[]=poor` filter all display the fit correctly. Verified across 7 reviewed candidates in Layer 5: the chip is absent EXACTLY when the score is 0.0 and present for every nonzero score (29.41, 65.29, 73.33, 88.24, 90.59, 100). The list API payload includes the status row with `score_percentage: 0`, so this is a frontend falsy-zero guard in the list rendering (pipeline known-failure #13 pattern).
- **Why MED, not HIGH:** pre-existing and out of scope. The list-chip code (`JobApplicationListContainer.tsx` and every other roleFit consumer outside the two feature files) has zero changes in the feature range `f8815555a..HEAD` (verified per-file), the identical absence was observed on fixture-seeded data before any feature code path ran, and re-scored candidates behave identically to never-re-scored ones. No SPEC requirement covers list chips.
- **History:** raised HIGH by Layer 5 run-3 round-1 agent 15; adjudicated MED by the orchestrator with the above evidence; independently VALIDATED as MED by three round-2 agents.
- **DISPOSITION (Jessica, 2026-07-13): CLOSED.** Already fixed by Jessica on another branch. Do not re-raise, do not fix here.

## MED-2 — Re-scoring unchanged inputs can produce a visually identical headline (observation)
Layer 5 round-2 agent 9 re-scored a candidate whose resume text and job criteria were unchanged since the prior organic review. The new review's HEADLINE came back byte-identical (provider determinism at the model level); the summary row itself was verifiably new (new id 2540, `rescore_requested: true` on the POST, credit consumed, new score/analysis rows). Not a defect — but a user who re-scores without changing the job description may perceive that "nothing happened." The Regenerate confirm modal's "Recommended when the resume has been updated or the job description has changed." copy already steers this.
- **DISPOSITION (Jessica, 2026-07-13): CLOSED — desired behavior.** "Re-scoring identical inputs should return identical headlines in the optimal world." Determinism on unchanged inputs is a feature (scoring-pipeline stability is deliberately tested); never report it as a defect.
